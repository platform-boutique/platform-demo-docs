# Next steps

The AWS platform (Terraform for the network, EKS, Cilium with SPIRE and WireGuard, gVisor nodes, RDS, the ALB and DNS; Argo CD, Kyverno, External Secrets, Dex and the developer portal from `platform-demo-helm`) is **merged to `main` in every repository but has not been deployed or verified on a live cluster**. Everything below is a backlog in priority order, not a record of what happened. Roadmap board: https://github.com/orgs/platform-boutique/projects/1.

1. **First Deploy and verification.** Run *Actions -> Deploy* in `infra-terraform` (plan, read it, approve on the `production` environment; about 25 minutes). Before it: the ALB address allow-list (`ALB_ALLOWED_CIDRS`) must be the browser's address, the GitHub OAuth App callback must be `https://dex.platform-demo.click/callback`, and the SSM parameters listed in `docs/secrets.md` of `infra-terraform` must exist. Afterwards follow "After the first real deploy: verify" in `gitops/README.md` of `platform-demo-helm`, run the live policy suite (`policies/tests/live/adversarial.sh`) and fix what a real cluster shows. Known risks that only a live apply can settle: WireGuard on the node AMI (fallback `cilium_encryption_enabled = false`), a SPIRE/operator deadlock (fallback `cilium_mutual_authentication_enabled = false`), the gVisor boot script and gVisor with Cilium's socket load balancing (fallback `sandbox: false` per namespace, or `socketLB.hostNamespaceOnly=true`), Argo CD adopting the Terraform install, the order of the sync waves, EBS CSI with IMDS hop limit 1, and the destroy preparation script.
2. **CI bridge: automatic promotion.** The reusable `gitops-promote` workflow in `platform-demo-workflows` (v3.1.0), a job in each service's `release.yaml` after `docker-promote`, and a GitHub App with auto-merge for dev. Until then the promotion PR is opened by hand ([CI/CD, branching and releases](cicd.md)). UAT and prod later, with a reviewed PR instead of auto-merge.
3. **Telemetry on EKS.** The services export OTLP to `alloy.monitoring.svc`, which does not exist there. Either deploy a collector and backends (the vendored charts in `platform-demo-helm/monitoring/`, or a managed option) or switch OTLP export off. Hubble metrics and Kyverno policy-report metrics belong in the same decision. See [Observability contract](observability.md).
4. **TechDocs publishing to S3.** A CI step per repository (`techdocs-cli generate` + `publish`), an S3 bucket and a role for the pipeline; the portal's Docs tab is empty until then.
5. **More environments.** `envs/uat` and `envs/prod` (and the shop on its own cluster, which the `cluster:` field of the workload lists already allows), with CODEOWNERS-reviewed promotion.
6. **Terraform tests.** Automated tests for the modules and for destroy cleanliness (`destroy-prepare.sh` and `destroy-verify.sh` have not run against a real cluster).
7. **Velero backups** (the portal's data is in RDS, the shop's `product-catalog-db` and SPIRE use EBS volumes), a **budget alarm**, and a **WAF** on the ALB.
8. **Security follow-ups.**
   - Retire the long-lived IAM access key of the Terraform user and use MFA/SSO instead; delete the classic GitHub token that was used for agent sessions.
   - A Kyverno rule that denies Services of type LoadBalancer in platform namespaces (the webhook skips `kube-system`).
   - Re-check the portal's two accepted CVEs (`braces`, `node-forge`, `.trivyignore.yaml`) before they expire on 2026-11-17; rebuild `app-ad-service` on a patched Alpine base (HIGH `libexpat` finding, PR open).
   - Redact card data in `payment-service`, graceful `SIGTERM` in Node/Python, JSON logs for cart, headless Services or a mesh for real gRPC balancing, Dockerfile base images pinned by digest, review the Node `.trivyignore` entries.
   - A registry without anonymous pull limits (ECR pull-through) so signature verification does not depend on a Docker Hub token; network policies for the remaining namespaces.
9. **Re-pin the ten services to workflows v3.0.3** (Trivy v0.76.1), by Dependabot or one re-pin PR per repository; and bump Argo CD to the current chart in Terraform **and** Git together.
10. **Option: Bottlerocket nodes.** A smaller attack surface, but gVisor is installed by a boot script on Amazon Linux 2023 and would not be available.
11. **Housekeeping.** Remove the Grafana links from the service catalog entries until a Grafana is deployed on the cluster,.
12. **Later.** Software templates (scaffolder) in the portal, synthetic tests, monitors and alerts (SLOs per service), semantic-versioning automation (conventional-commit PR titles, release-please), Crossplane for self-service infrastructure, AI tooling on top of the platform.
